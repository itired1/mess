# lilbrumessage 💌

Уютный мессенджер на двоих-на пятерых. Без аккаунтов в телефонах, без лишнего — открыл, зарегистрировался по имени, написал. Всё.

Сделан для себя и пары друзей: по-быстрому, без костылей, но с душой. И заодно как полигон, чтобы пощупать современный фронтенд + реальный вебсокет.

## Что умеет

- регистрация и вход по имени + паролю (пароль хранится в виде солёной scrypt-хэшки, без сисек)
- чаты один-на-один и общие группы
- живые сообщения по WebSocket: отправил — пришло сразу, без обновления страницы
- реакции (ёмодзи), ответы на сообщения, удаление своего сообщения
- галочки про чтение, «печатает…», онлайн-статус
- поиск по сообщениям в чате (Ctrl+F), подсветка совпадений
- аватарки и баннеры: PNG/JPG/WebP/GIF, анимированный GIF на баннере остаётся живым
- тёмная и светлая тема, настройка анимаций
- сообщения переживают перезапуск и сон сервера (SQLite тут не понадобился — хватает файла)

## Как запустить у себя

Нужен Node 18+.

```bash
npm install        # в корне
npm run build:all  # собрать сервер и клиент
npm start          # один процесс на порту 4000: и API, и статика
```

Открываешь http://localhost:4000 — и можно общаться.

Для разработки удобнее два процесса:

```bash
# терминал 1 — сервер
cd server
npm run dev

# терминал 2 — клиент с хот-релоадом
cd client
$env:VITE_SERVER_URL='http://localhost:4000'   # на Windows/PowerShell
npm run dev
```

Клиент поднимется на 5173, API слушает 4000.

## Переменные окружения

| Переменная | Что делает | По умолчанию |
| --- | --- | --- |
| `PORT` | порт сервера | `4000` |
| `CLIENT_ORIGIN` | откуда заходить в CORS | `http://localhost:5173` |
| `VITE_SERVER_URL` | куда клиенту ходить за API/Cокетами | адрес, где открыли страницу |
| `DB_PATH` | файл базы | `data/db.json` (рядом с сервером) |

## Деплой

Планировалось дёшево и сердито, без привязки карты:

- **Render (Blueprint)** — основной вариант. В репе лежит `render.yaml` с бесплатным Docker-сервисом. Пушаешь в GitHub → New Blueprint → всё. Минус бесплатной версии: после ~15 минут простоя инстанс засыпает и первое открытие долгое, а `data/` сбрасывается при редеплое.
- **Fly.io** — запасной, там нужен volume для `data/` (пример в `fly.toml`). Работает по-честному, но при регистрации просят карту.

Если совсем влом — можно и на localhost, а наружу прокинуть cloudflared `npm i -g cloudflared` + `cloudflared tunnel --url http://localhost:4000`. Правда, ссылка будет меняться каждый раз.

Весь флоу и объяснения — в файлах `render.yaml`, `Dockerfile`, `fly.toml`, они уже подстроены под проект.

## Структура

```
server/   Express + Socket.IO, REST + сокеты, файл-база data/db.json
client/   Vite + React + TypeScript, Material You палитра
data/     сюда складываются база и картинки (в гите не лежит)
```

## Проверки

```bash
cd server && npm run build     # сервер: tsc
cd client && npm run typecheck # клиент: tsc
cd client && npm run build     # клиент: vite build
```

Плюс есть e2e-проверки через настоящий клиент Socket.IO (регистрация, чаты, реакции, аватарки) и UI-тест в Playwright прямо против Chrome: вход, создание чата, отправка, позиция пузырей, поиск, профиль, логаут.

## Технологии

TypeScript, Node.js, Express, Socket.IO, React, Vite, чистый CSS. Никаких экосистемных тяжеловесов — всё честно и перечитаваемо.
